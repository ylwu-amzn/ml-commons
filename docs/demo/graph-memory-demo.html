Graph Memory vs Vanilla Memory — Live Comparison

Same 3 call notes ingested into both stores. All queries ran on OpenSearch 3.5 + ml-commons plugin (branch local-test/3.5, commit e19a0b368). Outputs below are verbatim from the live cluster.

Vanilla agentic memory stores conversation text. Neural search returns passages — good for "what did we discuss?", weak for "who is who, and how are they connected?"

Graph memory adds a structured layer. On every POST /memories, Claude Sonnet extracts entities and typed relationships automatically. The agent gets a queryable knowledge graph, not a bag of text.

Graph is opt-in per container via one line: "enable_graph": true.

  "configuration": {
    "embedding_model_type": "TEXT_EMBEDDING",
    "embedding_model_id": "BWxf0J0BTxnG51e8Pch9",
    "embedding_dimension": 384,
    "llm_id": "3qRp0J0BQ4F7Y_V3OOKT",
    "index_prefix": "demo",
    "enable_graph": true,
    "use_system_index": false,
    "parameters": { "llm_result_path": "$.output.message.content[0].text" }
  }
}
POST /_plugins/_ml/memory_containers/_YWw0J0BFKsTOMMlBkoK/memories
{
  "messages": [{
    "role": "user",
    "content": [{
      "type": "text",
      "text": "Had a great call with Elena Torres today. She is VP of Engineering at Northwind Traders. Northwind runs all their analytics on PostgreSQL. Elena is researching vector databases for their next platform. I met her at KubeCon last quarter. My manager Sarah Kim said I should loop in Ravi Patel from our SE team. Ravi used to work with Tom Becker at Acme five years ago; Tom is now Data Architect at Umbrella Corp."
    }]
  }],
  "infer": true
}
Repeat the second request for each call note. The server runs Sonnet in parallel with the normal memory write and indexes the extracted entities/relationships automatically.

Q4. Contacts at companies that compete with our customers

Honest limit: the LLM's default relationship vocabulary doesn't include COMPETES_WITH, so Sonnet labeled competition as OTHER. Fixable by pointing the container at a custom_relationship_extraction_prompt with a domain vocabulary.

Graph same limit — blocked at schema

Typed COMPETES_WITH edge doesn't exist because the default prompt's vocabulary is:
WORKS_AT / KNOWS / CREATED / USES / PART_OF / LOCATED_IN / MANAGES / COLLABORATES_WITH / DEVELOPED_BY / OTHER.
Remediation is already plumbed in: the configuration.parameters field accepts a custom_relationship_extraction_prompt. Exposing this in Dashboards closes the gap without code changes.

Dev Tools — native graph search endpoint

The /_plugins/_ml/memory_containers/{id}/memories/graph/_search endpoint supports three modes with one REST shape.

1) Text search — neural entity lookup by name

POST /_plugins/_ml/memory_containers/_YWw0J0BFKsTOMMlBkoK/memories/graph/_search
{
  "query": "Elena",
  "search_type": "text",
  "top_k": 5
}

2) Hybrid (default) — neural + 1-hop relationship expansion

POST /_plugins/_ml/memory_containers/_YWw0J0BFKsTOMMlBkoK/memories/graph/_search
{
  "query": "vector databases",
  "top_k": 10
}

3) Traversal — BFS from a known entity

POST /_plugins/_ml/memory_containers/_YWw0J0BFKsTOMMlBkoK/memories/graph/_search
{
  "query": "Elena",
  "search_type": "traversal",
  "entity_id": "ent:_YWw0J0BFKsTOMMlBkoK:person:elena-torres",
  "max_depth": 2
}

Supporting endpoints

GET /_plugins/_ml/memory_containers/_YWw0J0BFKsTOMMlBkoK/memories/graph/entities?query=*&top_k=50
DELETE /_plugins/_ml/memory_containers/_YWw0J0BFKsTOMMlBkoK/memories/graph
Every request above works as-is in OpenSearch Dashboards → Dev Tools. Paste, hit the green "play" arrow, and the response appears on the right. Replace the container id (_YWw0J0BFKsTOMMlBkoK) with yours if you're running a fresh install.
