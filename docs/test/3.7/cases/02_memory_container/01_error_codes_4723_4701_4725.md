# Memory Container 01 — 404 error codes — PR #4723, #4701, #4725

- **Area:** Memory containers + context management
- **PRs:**
  - [#4723](https://github.com/opensearch-project/ml-commons/pull/4723) — fix wrong error code when deleting memory container
  - [#4701](https://github.com/opensearch-project/ml-commons/pull/4701) — delete context management template returns 404 (was 500)
  - [#4725](https://github.com/opensearch-project/ml-commons/pull/4725) — `OpenSearchStatusException` → `OpenSearchException` for broader 4xx coverage
- **Status:** PASS
- **Date:** 2026-05-22

## Goal

Pre-3.6, deleting (and getting) non-existent resources for memory container or context
management templates returned **500 Internal Server Error**. The fix: return **404 Not Found**.

## Steps

### Step 1 — DELETE non-existent memory container

```bash
oc -X DELETE "$OS_URL/_plugins/_ml/memory_containers/does_not_exist_id" \
   -w "\n[HTTP_STATUS:%{http_code}]"
```

Response:

```json
{
  "error": {
    "root_cause": [{"type":"status_exception","reason":"Memory container not found"}],
    "type":"status_exception",
    "reason":"Memory container not found"
  },
  "status": 404
}
```

`HTTP_STATUS: 404`. PASS.

### Step 2 — DELETE non-existent context management template

```bash
oc -X DELETE "$OS_URL/_plugins/_ml/context_management/does_not_exist_id" \
   -w "\n[HTTP_STATUS:%{http_code}]"
```

Response:

```json
{
  "error":{"root_cause":[{"type":"status_exception","reason":"Context management template not found: does_not_exist_id"}],
           "type":"status_exception",
           "reason":"Context management template not found: does_not_exist_id"},
  "status":404
}
```

`HTTP_STATUS: 404`. PASS.

### Step 3 — GET non-existent (regression sweep)

GET memory container → 404 (`"Failed to find memory container with the provided memory container id: does_not_exist_id"`).
GET context management → 404 (`"Context management not found: does_not_exist_id"`).

## Result

PASS — both DELETE and GET return 404 for missing resources.

## Notes

- The error message wording differs slightly between resources ("not found" vs "Failed to
  find … with the provided memory container id …") — not a bug, but worth documenting if a
  client SDK keys off message text.
- #4725 widened the catch from `OpenSearchStatusException` to `OpenSearchException`. We didn't
  exercise a transport-side failure here, but the 404 semantics confirm the catch path is no
  longer letting these escape as 500.
